# 오라클 무료 서버에 올리기

> 👉 **구글 클라우드**로 하려면 [README-google.md](README-google.md) 를 보세요.

교회 관리 시스템을 **오라클 클라우드 무료 서버**에 올려서, 링크 하나로 어디서든 쓰는 방법입니다.
처음 한 번은 30분~1시간 정도 걸립니다. 그 다음부터는 명령 한 줄로 업데이트합니다.

> 오라클 화면의 메뉴 이름·위치는 조금씩 바뀔 수 있습니다. 비슷한 이름을 찾아 진행하세요.

---

## 전체 흐름

```
[1] 오라클 가입  →  [2] 서버 만들기  →  [3] 포트 열기  →  [4] 내 PC에서 npm run deploy  →  [5] 관리자 계정 만들기
```

---

## 1. 오라클 클라우드 가입

1. https://www.oracle.com/kr/cloud/free/ 접속 → **무료로 시작하기**
2. 이메일, 이름, 주소, 휴대폰 인증
3. **홈 리전(Home Region)** 선택: **South Korea Central (Seoul)** 또는 **South Korea North (Chuncheon)**
   - ⚠️ 나중에 바꿀 수 없고, 무료 서버는 홈 리전에서만 만들 수 있습니다.
4. **카드 인증**: 본인 확인용입니다. 무료 범위(Always Free)만 쓰면 요금이 나가지 않습니다.
   - 가입 후 "유료 계정으로 업그레이드" 버튼은 누르지 마세요.
5. 가입 완료 메일이 오고 콘솔에 로그인되면 다음 단계로.

---

## 2. 서버(인스턴스) 만들기

1. 콘솔 왼쪽 위 메뉴 ☰ → **컴퓨트(Compute)** → **인스턴스(Instances)** → **인스턴스 생성(Create instance)**
2. **이름**: `church` (아무거나)
3. **이미지와 구성(Image and shape)** → **편집**
   - **이미지**: `Canonical Ubuntu` → **24.04** (또는 22.04)
   - **구성(Shape)**: 아래 둘 중 하나 (둘 다 **"항상 무료 적격(Always Free-eligible)"** 표시가 있어야 함)
     - **Ampere `VM.Standard.A1.Flex`** — OCPU 1개, 메모리 6GB 추천 (성능 좋음)
     - **AMD `VM.Standard.E2.1.Micro`** — 메모리 1GB (A1 이 "용량 부족"으로 안 만들어질 때)
4. **네트워킹**: 기본값(새 가상 클라우드 네트워크 생성, **공용 IPv4 주소 할당** 체크)
5. **SSH 키 추가(Add SSH keys)** → **키 쌍 생성(Generate a key pair for me)** → **개인 키 저장(Save private key)**
   - `ssh-key-2026-xx-xx.key` 같은 파일이 내려받아집니다.
   - ⚠️ **이 파일이 서버 열쇠입니다.** 잃어버리면 서버에 들어갈 수 없고, 남에게 주면 안 됩니다.
   - 안전한 곳으로 옮겨 두세요. 예) `C:\Users\본인\.ssh\church.key`
6. **생성(Create)** → 1~2분 뒤 상태가 **실행 중(Running)** 이 됩니다.
7. 인스턴스 상세 화면의 **공용 IP 주소(Public IP address)** 를 메모하세요. 예) `152.70.11.22`

> "Out of capacity(용량 부족)" 오류가 나면: 몇 시간 뒤 다시 시도하거나, E2.1.Micro 로 만드세요.

## 3. 웹 포트(80, 443) 열기

오라클은 기본으로 SSH(22번)만 열려 있습니다. 웹사이트용 포트를 열어야 합니다.

1. 인스턴스 상세 화면 → **서브넷(Subnet)** 링크 클릭 (또는 ☰ → 네트워킹 → 가상 클라우드 네트워크 → 방금 만든 VCN)
2. **보안 목록(Security Lists)** → **Default Security List for ...** 클릭
3. **수신 규칙 추가(Add Ingress Rules)** 두 번:

   | 소스 CIDR | IP 프로토콜 | 대상 포트 범위 | 설명 |
   |---|---|---|---|
   | `0.0.0.0/0` | TCP | `80` | http |
   | `0.0.0.0/0` | TCP | `443` | https |

> 서버 안쪽 방화벽은 설치 스크립트가 자동으로 열어 줍니다.

## 4. 내 PC에서 올리기

`D:\testProject` 폴더에서 터미널을 열고:

```bash
npm run deploy
```

처음 실행하면 세 가지를 물어봅니다. (다음부터는 묻지 않습니다)

| 질문 | 입력 예 |
|---|---|
| 오라클 서버 공용 IP | `152.70.11.22` |
| SSH 개인 키 파일 경로 | `C:\Users\본인\.ssh\church.key` |
| 도메인 | 그냥 **Enter** → 무료 주소 `152-70-11-22.sslip.io` 사용 |

그 다음 자동으로:
1. 화면 + Spring 을 jar 파일 하나로 빌드
2. 서버로 업로드
3. 서버에서 Java·웹서버 설치, HTTPS 인증서 발급, 자동 시작 등록

마지막에 이런 화면이 나오면 성공입니다.

```
  성도 화면 :  https://152-70-11-22.sslip.io/
  관리자 화면:  https://152-70-11-22.sslip.io/admin

  ▶ 관리자 계정을 아직 만들지 않았습니다.
        설치 코드:  K7QM3XPA
```

> 처음 서버에 접속할 때 `Are you sure you want to continue connecting?` 이 나오면 `yes` 입력.

---

## 5. 관리자 계정 만들기

1. **관리자 화면** 주소로 접속
2. **설치 코드**(위 화면의 8자리) + 이름·아이디·비밀번호 입력 → 관리자 계정 생성
   - 설치 코드는 설치 직후 다른 사람이 먼저 관리자 계정을 만드는 것을 막기 위한 것입니다.
3. `관리 > 설정`에서 **교회 이름**, 헌금 종류, 계정과목을 교회에 맞게 수정
4. `관리 > 사용자 관리`에서 재정 담당, 교역자 계정 추가
5. 성도들에게는 **성도 화면 주소**만 공유하세요.

> 서버에는 **샘플 데이터 없이 깨끗한 상태**로 시작합니다. (내 PC의 샘플 데이터는 올라가지 않습니다)

## 업데이트 (코드를 고친 뒤)

```bash
npm run deploy
```

같은 명령으로 새 버전이 올라가고 서버가 재시작됩니다. **데이터와 백업은 그대로 유지됩니다.**

---

## 백업

- 서버에서 **매일 자동 백업**됩니다. (`/opt/church/backups`, 최근 30개)
- 하지만 서버 자체에 문제가 생기면 백업도 같이 잃을 수 있으니,
  **한 달에 한 번 이상 `관리 > 백업·복원`에서 다운로드**해서 PC·USB·클라우드에 보관하세요.
- 오라클은 오래 거의 사용하지 않는 무료 서버를 회수할 수 있습니다. 시범 운영 중에도 가끔 접속하고, 백업은 꼭 따로 받아 두세요.

---

## 문제가 생기면

서버에 직접 접속:

```bash
ssh -i C:\Users\본인\.ssh\church.key ubuntu@152.70.11.22
```

| 확인할 것 | 명령 (서버에서) |
|---|---|
| 프로그램 상태 | `sudo systemctl status church` |
| 프로그램 로그 | `sudo journalctl -u church -n 100` |
| 웹서버(HTTPS) 로그 | `sudo journalctl -u caddy -n 50` |
| 프로그램 재시작 | `sudo systemctl restart church` |

| 증상 | 원인 / 해결 |
|---|---|
| `npm run deploy` 에서 업로드 실패 | IP 오타, 키 파일 경로, 서버가 꺼져 있는지 확인 |
| 주소 접속이 안 됨 (시간 초과) | 3단계 포트(80, 443) 열기를 했는지 확인 |
| 접속은 되는데 "안전하지 않음" | 인증서 발급 중일 수 있음. 1~2분 뒤 다시. 계속되면 caddy 로그 확인 |
| 설치 코드를 잊어버림 | 서버에서 `sudo grep SETUP_TOKEN /etc/church.env` |
| 서버 접속 정보를 바꾸고 싶음 | `deploy\server.local.json` 파일을 지우고 `npm run deploy` 다시 실행 |

## 나중에: 우리 교회 주소 쓰기

`152-70-11-22.sslip.io` 대신 `우리교회.kr` 같은 주소를 쓰려면:
1. 도메인 구입 (연 1~2만 원)
2. 도메인 관리 화면에서 **A 레코드** → 서버 공용 IP 로 연결
3. `deploy\server.local.json` 의 `domain` 을 새 주소로 바꾸고 `npm run deploy`
