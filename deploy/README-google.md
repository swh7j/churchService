# 구글 클라우드 무료 서버에 올리기

교회 관리 시스템을 **구글 클라우드(GCP) 무료 서버(e2-micro)** 에 올려서, 링크 하나로 어디서든 쓰는 방법입니다.
처음 한 번은 30분~1시간 정도 걸리고, 그 다음부터는 `npm run deploy` 한 줄로 업데이트합니다.

> 구글 화면의 메뉴 이름·위치는 조금씩 바뀔 수 있습니다. 비슷한 이름을 찾아 진행하세요.

---

## 먼저 알아둘 것 (비용)

| 항목 | 내용 |
|---|---|
| 무료 서버 | **e2-micro 1대** — 단, **미국 리전(오리건 us-west1 / 아이오와 us-central1 / 사우스캐롤라이나 us-east1)만** 무료 |
| 무료 디스크 | **표준 영구 디스크 30GB** (⚠️ 기본값인 '균형 있는 영구 디스크'는 무료가 아님) |
| 무료 데이터 전송 | 월 1GB (교회 한 곳이 쓰기에는 보통 충분) |
| 신규 가입 크레딧 | **$300 / 90일** — 이 기간에 조금 나오는 요금은 크레딧에서 빠짐 |
| ⚠️ 외부 IP | 구글 요금표상 **외부 IP 주소에 시간당 소액이 붙을 수 있습니다** (월 수천 원 수준). 무료 체험 기간 이후 결제 화면에서 꼭 확인하세요 |

- 미국 서버라 한국에서 접속하면 **조금 느립니다**(0.1~0.2초 정도 지연). 교회 관리 시스템 사용에는 큰 문제 없습니다.
- 메모리가 1GB 로 작아서, 설치 스크립트가 **가상 메모리(스왑) 2GB 를 자동으로 추가**합니다.

## 전체 흐름

```
[1] 가입  →  [2] 예산 알림  →  [3] 내 PC에서 SSH 키 만들기  →  [4] 서버 만들기  →  [5] npm run deploy  →  [6] 관리자 계정
```

## 1. 구글 클라우드 가입

1. https://console.cloud.google.com 접속 → **개인 구글 계정**으로 로그인
2. 위쪽의 **무료로 시작하기(무료 체험판 시작)** 클릭
3. 국가: **대한민국**, 약관 동의
4. **결제 정보(카드)** 입력 — 본인 확인용. 무료 체험판 동안은 자동으로 결제되지 않습니다.
5. 가입이 끝나면 콘솔 첫 화면이 나옵니다. (프로젝트 `My First Project` 가 자동으로 생깁니다)

---

## 2. 예산 알림 설정 (꼭 해두세요)

예상치 못한 요금이 생기면 메일로 알려주게 합니다.

1. 왼쪽 위 ☰ → **결제(Billing)** → **예산 및 알림(Budgets & alerts)** → **예산 만들기**
2. 금액: **1,000원** (또는 5,000원)
3. 알림 기준: 50%, 90%, 100% (기본값 그대로)
4. **완료**

> 예산 알림은 **알려주기만** 하고 자동으로 막지는 않습니다. 메일이 오면 결제 화면에서 무엇이 청구되는지 확인하세요.

---

## 3. 내 PC에서 SSH 키 만들기

서버에 들어가는 **열쇠 파일**을 만듭니다. PowerShell 을 열고:

```powershell
ssh-keygen -t ed25519 -f $HOME\.ssh\church-gcp -C deploy
```

- 비밀번호(passphrase)를 물으면 그냥 **Enter 두 번** (또는 원하는 비밀번호)
- 두 파일이 생깁니다:
  - `C:\Users\본인\.ssh\church-gcp` ← **개인 키 (절대 남에게 주지 마세요)**
  - `C:\Users\본인\.ssh\church-gcp.pub` ← 공개 키 (서버에 등록할 것)

공개 키 내용을 복사합니다:

```powershell
Get-Content $HOME\.ssh\church-gcp.pub
```

`ssh-ed25519 AAAA.... deploy` 처럼 한 줄이 나옵니다. **이 한 줄 전체를 복사**해 두세요.
(맨 끝의 `deploy` 가 서버 사용자 이름이 됩니다)

---

## 4. 서버(VM) 만들기

1. 왼쪽 위 ☰ → **Compute Engine** → **VM 인스턴스**
   - 처음이면 **"Compute Engine API 사용 설정"** 버튼이 나옵니다 → 클릭하고 1~2분 기다리기
2. **인스턴스 만들기(Create instance)**
3. **머신 구성**
   - 이름: `church`
   - 리전: **`us-west1 (오리건)`** ← 무료 리전 중 한국에서 가장 가까움
   - 영역: 아무거나 (예: us-west1-b)
   - 시리즈: **E2** → 머신 유형: **`e2-micro`**
   - 오른쪽에 월 예상 비용이 표시되어도, 무료 등급 할인은 반영되지 않은 금액이니 놀라지 마세요.
4. **OS 및 스토리지** → **변경**
   - 운영체제: **Ubuntu**
   - 버전: **Ubuntu 24.04 LTS** (x86/64, `amd64`. `Arm64` 아님)
   - 부팅 디스크 유형: **표준 영구 디스크(Standard persistent disk)** ⚠️ 꼭 바꾸세요
   - 크기: **30** GB
   - **선택**
5. **네트워킹**
   - 방화벽: **HTTP 트래픽 허용** ✅, **HTTPS 트래픽 허용** ✅
6. **보안** → **SSH 키 관리(Manage SSH keys)** → **항목 추가(Add item)**
   - 3단계에서 복사한 **공개 키 한 줄**을 붙여넣기
7. **만들기(Create)** → 1분쯤 뒤 초록 체크 표시가 나오면 완료
8. 목록의 **외부 IP(External IP)** 를 메모하세요. 예) `34.82.11.22`

## 5. 내 PC에서 올리기

`D:\testProject` 폴더에서 터미널을 열고:

```bash
npm run deploy
```

처음 실행하면 네 가지를 물어봅니다. (다음부터는 묻지 않습니다)

| 질문 | 입력 |
|---|---|
| 서버 외부(공용) IP | 4단계에서 메모한 IP. 예) `34.82.11.22` |
| SSH 개인 키 파일 경로 | `C:\Users\본인\.ssh\church-gcp` (**.pub 아닌 파일**) |
| 서버 사용자 이름 | **`deploy`** |
| 도메인 | 그냥 **Enter** → 무료 주소 `34-82-11-22.sslip.io` |

> 처음 접속할 때 `Are you sure you want to continue connecting?` 이 나오면 `yes`.

자동으로 빌드 → 업로드 → 서버 설치가 진행되고, 마지막에 이런 화면이 나오면 성공입니다.

```
  성도 화면 :  https://34-82-11-22.sslip.io/
  관리자 화면:  https://34-82-11-22.sslip.io/admin

  ▶ 관리자 계정을 아직 만들지 않았습니다.
        설치 코드:  K7QM3XPA
```

---

## 6. 관리자 계정 만들기

1. **관리자 화면** 주소로 접속 (처음엔 HTTPS 인증서를 받느라 10~30초 걸릴 수 있음)
2. **설치 코드** + 이름·아이디·비밀번호 입력 → 관리자 계정 생성
3. `관리 > 설정`에서 교회 이름, 헌금 종류, 계정과목 수정
4. `관리 > 사용자 관리`에서 재정 담당, 교역자 계정 추가
5. 성도들에게는 **성도 화면 주소**만 공유

> 서버는 **샘플 데이터 없이 깨끗한 상태**로 시작합니다.

## 업데이트 (코드를 고친 뒤)

```bash
npm run deploy
```

데이터와 백업은 그대로 유지됩니다.

---

## 주의할 점

- **VM 을 중지했다가 다시 켜면 외부 IP 가 바뀔 수 있습니다.** 그러면 주소(sslip.io)도 바뀝니다.
  → 서버는 계속 켜 두세요. IP 가 바뀌었다면 `deploy\server.local.json` 을 지우고 `npm run deploy` 를 다시 실행하세요.
- **무료 체험 90일이 끝나면** 콘솔에서 "전체 계정으로 업그레이드" 하라는 안내가 나옵니다. 업그레이드해야 서버가 계속 유지되며, 이후에는 **무료 범위를 넘는 부분만** 청구됩니다.
- **한 달에 한 번** `결제 > 보고서`에서 청구 금액을 확인하세요.
- 서버 자체에 문제가 생길 수 있으니 `관리 > 백업·복원`에서 **백업을 정기적으로 다운로드**하세요.

## 문제가 생기면

서버에 직접 접속:

```bash
ssh -i C:\Users\본인\.ssh\church-gcp deploy@34.82.11.22
```

| 확인할 것 | 명령 (서버에서) |
|---|---|
| 프로그램 상태 | `sudo systemctl status church` |
| 프로그램 로그 | `sudo journalctl -u church -n 100` |
| 웹서버(HTTPS) 로그 | `sudo journalctl -u caddy -n 50` |
| 설치 코드 다시 보기 | `sudo grep SETUP_TOKEN /etc/church.env` |

| 증상 | 해결 |
|---|---|
| `Permission denied (publickey)` | 사용자 이름이 `deploy` 인지, 4-6단계에 공개 키를 넣었는지, 개인 키 경로가 맞는지 확인 |
| 주소 접속 시간 초과 | 4-5단계 HTTP/HTTPS 트래픽 허용 체크 확인 (VM 수정 화면에서 바꿀 수 있음) |
| "안전하지 않음" 표시 | 인증서 발급 중일 수 있음. 1~2분 뒤 다시. 계속되면 caddy 로그 확인 |
| 화면이 매우 느림 | 메모리 1GB 한계. 사용자가 늘면 유료 서버(월 5~7천 원)로 옮기는 것을 검토 |
