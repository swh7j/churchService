# 구글 클라우드 무료 서버에 올리기

구글 클라우드(GCP)의 무료 서버(e2-micro)에 올려서 링크 하나로 쓰는 방법입니다.
처음 설정은 30분에서 1시간쯤 걸리고, 그다음부터는 `npm run deploy` 로 업데이트합니다.

구글 콘솔은 메뉴 이름이나 위치가 가끔 바뀝니다. 안 보이면 비슷한 이름을 찾으면 됩니다.

## 비용

| 항목 | 내용 |
|---|---|
| 무료 서버 | e2-micro 1대. 미국 리전(us-west1 오리건, us-central1 아이오와, us-east1 사우스캐롤라이나)만 무료 |
| 무료 디스크 | 표준 영구 디스크 30GB. 기본값인 '균형 있는 영구 디스크'는 무료가 아님 |
| 데이터 전송 | 월 1GB 무료. 교회 한 곳이 쓰기에는 보통 충분 |
| 신규 가입 크레딧 | 90일 동안 $300 |
| 외부 IP | 시간당 소액이 붙을 수 있음(월 수천 원 수준). 무료 체험이 끝난 뒤 결제 화면에서 확인 |

미국 서버라 한국에서는 0.1~0.2초쯤 늦습니다. 써 보면 크게 거슬리지는 않습니다.
메모리가 1GB 뿐이라 설치 스크립트가 스왑 2GB 를 알아서 붙입니다.

## 순서

```
가입 → 예산 알림 → SSH 키 만들기 → 서버 만들기 → npm run deploy → 관리자 계정
```

## 1. 가입

1. https://console.cloud.google.com 에 개인 구글 계정으로 로그인
2. 무료 체험판 시작
3. 국가는 대한민국, 약관 동의
4. 결제 카드 입력(본인 확인용, 무료 체험 동안은 자동 결제되지 않음)
5. 가입이 끝나면 `My First Project` 프로젝트가 자동으로 생깁니다

## 2. 예산 알림

예상하지 못한 요금이 생기면 메일로 받기 위한 설정입니다.

1. 메뉴 → 결제(Billing) → 예산 및 알림(Budgets & alerts) → 예산 만들기
2. 금액 1,000원(또는 5,000원), 알림 기준은 기본값(50%, 90%, 100%)

예산 알림은 알려 주기만 하고 서버를 멈추지는 않습니다. 메일이 오면 결제 화면에서 무엇이 청구됐는지 보면 됩니다.

## 3. SSH 키 만들기 (내 PC)

PowerShell 에서:

```powershell
ssh-keygen -t ed25519 -f $HOME\.ssh\church-gcp -C deploy
Get-Content $HOME\.ssh\church-gcp.pub
```

암호(passphrase)는 비워 둬도 됩니다. 파일이 두 개 생깁니다.

- `church-gcp`: 개인 키. 다른 사람에게 주면 안 됨
- `church-gcp.pub`: 공개 키. 서버에 등록할 것

두 번째 명령으로 나오는 `ssh-ed25519 AAAA.... deploy` 한 줄을 복사해 둡니다. 끝의 `deploy` 가 서버 사용자 이름이 됩니다.

## 4. 서버 만들기

Compute Engine → VM 인스턴스 → 인스턴스 만들기. 처음이면 Compute Engine API 사용 설정이 먼저 나옵니다.

| 항목 | 값 |
|---|---|
| 이름 | `church` |
| 리전 | `us-west1`(오리건). 무료 리전 중 한국에서 가장 가까움 |
| 머신 | E2 → `e2-micro` |
| OS | Ubuntu 24.04 LTS (x86/64, Arm64 아님) |
| 부팅 디스크 | 표준 영구 디스크, 30GB. 기본값에서 바꿔야 무료 |
| 방화벽 | HTTP, HTTPS 트래픽 허용 |
| 보안 → SSH 키 | 3단계에서 복사한 공개 키 한 줄 |

오른쪽에 월 예상 비용이 나오는데, 무료 등급 할인이 빠진 금액이라 실제와 다릅니다.
만들고 1분쯤 지나면 목록에 외부 IP(예: `34.82.11.22`)가 나옵니다.

## 5. 올리기 (내 PC)

프로젝트 폴더에서:

```bash
npm run deploy
```

처음 한 번만 네 가지를 묻습니다. 답은 `deploy/server.local.json` 에 저장되고, 이 파일은 저장소에 올라가지 않습니다.

| 질문 | 입력 |
|---|---|
| 서버 외부 IP | 4단계의 IP |
| SSH 개인 키 경로 | `C:\Users\본인\.ssh\church-gcp` (.pub 아닌 파일) |
| 서버 사용자 이름 | `deploy` |
| 도메인 | 비워 두면 무료 주소 `34-82-11-22.sslip.io` |

처음 접속할 때 `Are you sure you want to continue connecting?` 이 나오면 `yes` 를 입력합니다.
그다음은 빌드, 업로드, 서버 설치까지 알아서 돌아갑니다. 끝나면 접속 주소와 설치 코드가 나옵니다.

## 6. 관리자 계정

1. 관리자 화면 주소로 접속(처음엔 HTTPS 인증서를 받느라 10~30초 걸릴 수 있음)
2. 설치 코드와 이름, 아이디, 비밀번호를 넣어 관리자 계정 생성
3. 설정에서 교회 이름, 헌금 종류, 계정과목 정리
4. 사용자 관리에서 재정 담당, 교역자 계정 추가

성도들에게는 성도 화면 주소만 알려 주면 됩니다. 서버는 빈 상태로 시작합니다.

## 업데이트

코드를 고친 뒤 `npm run deploy` 를 다시 실행합니다. 데이터와 백업은 그대로 남습니다.

## 운영하면서 알아 둘 것

- VM 을 껐다 켜면 외부 IP 가 바뀔 수 있고, 그러면 sslip.io 주소도 바뀝니다. IP 가 바뀌었다면 `deploy/server.local.json` 을 지우고 다시 배포합니다.
- 무료 체험 90일이 끝나면 전체 계정으로 업그레이드해야 서버가 유지됩니다. 그 뒤에는 무료 범위를 넘는 부분만 청구됩니다.
- 청구 금액은 결제 → 보고서에서 볼 수 있습니다.
- 서버 밖에도 백업이 있도록 관리자 화면의 백업·복원에서 가끔 내려받아 둡니다(30일이 지나면 대시보드에 알림).

## 문제가 생기면

서버 접속:

```bash
ssh -i C:\Users\본인\.ssh\church-gcp deploy@34.82.11.22
```

| 확인할 것 | 명령 (서버에서) |
|---|---|
| 프로그램 상태 | `sudo systemctl status church` |
| 프로그램 로그 | `sudo journalctl -u church -n 100` |
| HTTPS(Caddy) 로그 | `sudo journalctl -u caddy -n 50` |
| 설치 코드 다시 보기 | `sudo grep SETUP_TOKEN /etc/church.env` |

| 증상 | 확인할 곳 |
|---|---|
| `Permission denied (publickey)` | 사용자 이름이 `deploy` 인지, 서버에 공개 키를 넣었는지, 개인 키 경로가 맞는지 |
| 접속 시간 초과 | VM 의 HTTP/HTTPS 트래픽 허용 (VM 수정 화면에서 바꿀 수 있음) |
| "안전하지 않음" 표시 | 인증서 발급 중일 수 있음. 1~2분 뒤 다시 보고, 계속되면 Caddy 로그 |
| 화면이 매우 느림 | 메모리 1GB 한계. 사용자가 늘면 유료 서버(월 5~7천 원) 검토 |
